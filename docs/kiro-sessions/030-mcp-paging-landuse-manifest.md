## 1. MCP tools (found by the plate-qa agent on its first real run)

The agent reached the server and read both plates' alignment and decision counts, then stopped:
`features_near` returned 163 features as 199 KB with no paging or filter and was truncated by the
client; `plate_work` gave weakness counts but no ids or crops. Fix the tools so an agent can do
plate QA without reading files by hand:
- `features_near`: optional `source` filter, `limit` and `cursor`, and a `compact` mode (id, kind,
  confidence, area, centroid, crop rectangle, has-storeys, confirmed-by, same_as count) that keeps
  100 features under 20 KB. State the total and whether more remain.
- `plate_work`: list flagged proposals with id, flags, score, area and crop rectangle, paged.
- A new `plate_features` tool: for one source, every published feature in compact form plus, per
  feature, whether its centroid lies inside the plate's control hull (a fact from the alignment
  record, computed with shapely), paged.
- Every tool's result fits in 20 KB or says how to get the rest. Tests for size bounds and paging.
Update `.kiro/agents/` nothing (the maintainer edits agents); say in your report which tool names
the plate-qa agent should be told about.

## 2. Land-use areas

Past land use is the practical value of Buried. A reviewer must be able to record an area (a
yard, a works, a factory lot) with the use as lettered on the plate. Implement the publish side:
a `trace` decision carrying a pixel polygon, `kind: land_use`, the use text as lettered and the
crop it was read from, validated and published as a `use_` feature with the same provenance,
position error and reviewer rules as buildings (spec 04 group 19 and the group 2 items it needs).
The service's publish endpoint accepts it. Properties: a land-use area without lettered text and
a crop is refused; published areas never overlap the plate's outside-map-area; ids are stable.

## 3. A committed plate manifest

The Studio client refuses a plate whose `plate_ref` is unknown, and on an empty deployment that
comes only from a manifest. Decision: commit `data/plate_manifest.json` holding, for each
registered plate, its URL, file names, sizes and SHA-256 (no rasters), generated by a command
(`buried manifest`) from `data/raw/manifest.json`, validated by `buried validate`, and read by the
service as the default manifest. The held-out plate's entry is allowed (a hash is not a result).
Run the command for real and commit the file.

Never weaken a property. Narrow tests while iterating, full suite once at the end. Commit per
item; tick tasks only when tests pass. Do not push. Short final report.
